I've reviewed the whole design against decisions.md A, B2 and B3, without editing anything. The design meets most structural rulings. The serious problems are in four places: array GPURefs (the "boxes" plots use as attributes), eviction, combining pending TLAS builds, and index buffers. Several of the "no recompile" promises also break in realistic plot changes. I re-read every line cited below.

Abbreviations, all in `/sim/Programmieren/VideoEdit/dev/Mantle/docs/`: **plan** = recording-plan.md, **int** = internals.jl, **rr** = resizing-and-raytracing.jl, **api** = api.md, **ex** = examples.jl. "Box" = `ArrayBox`, the GPURef of an array (rr:638).

## 2. Violating scenarios and proposed fixes

### RayMakie plot changes

| Change | What the design does | Recompile or reallocation |
|---|---|---|
| Same-length data | Store into the plot's own array (rr:803-804) | Nothing recompiles. Every store allocates a staging region (rr:351), although plan:937-939 promises inline stores up to 64 KiB with no staging. |
| New length | `resize!` of the own array; draws over a box are indirect (rr:669-672) | No recompile. The first resize always moves (scenario 14) and `copy!` copies the old contents first (scenario 15). |
| Value ↔ per-element | Same array resized | none |
| Device array swapped in | `r[] = b`, a pending cell write (rr:655-666) | No recompile. But: the ordering race (scenario 1); a view loses its offset (scenario 18); another element type or dimension throws (api:398). |
| Visibility | Store into a flag, `when!(p, flag)` (rr:809-816) | Fine on Vulkan. Metal conditional draws are unspecified (plan:1344-1351). Traced: `RangeEntry` has no mask field, only `active`, and active↔inactive needs a full build (rr:469-475, rr:23-25 vs plan:885). |
| Colormap / colorrange | Stores; a new texture index for a new size | No recompile, unless colour switches between numbers and colours: that is a new pipeline (plan:1277). |
| Camera | One-element store | none |
| Window resize | Mark, then a new generation at the next run | Raster: fine within capacity. Beyond capacity the docs contradict each other: "throws" (plan:424, plan:1517, ex:453) vs "recompiles" (plan:837-838, api:175, int:847). Traced: the integrator graph is "declared once per screen and film size" (plan:1314), so a resize means a new graph. |
| Axis layout change | Store into the scene rectangle | No recompile, but `rect` lives in each RenderObject (rr:798), so it is N stores. A traced LScene changes film size → new integrator graph. |
| Marker change | SDF shape is already a runtime `Int32` in RayMakie (overlay/scatter.jl:193) → store | Image markers and meshscatter marker meshes are unspecified; a marker mesh hits the index-buffer problem (scenario 13). |
| Transparency / draw order | — | **recompiles** (plan:1320-1321) |
| Image size change | New image under a new index (plan:960-963) | No recompile. Unspecified: whether contents are kept, and which layout an image created after compile is in (image barriers record the VkImage handle). |
| Glyph atlas growth | New index (rr:837-838) | UVs are stored normalised and the atlas width is a compile-time constant (RayMakie overlay/scatter.jl:195, :426). Growth needs new UVs in every text and scatter plot (a walk) or a recompile. |
| Text content | Resizes | none |
| Lines with NaN breaks | RayMakie draws an adjacency index list built from the NaN pattern (overlay/lines.jl:515-519, :568) | Index buffers are bound by handle (rr:429-430). Any move (first resize, doubling, beyond the reserve) **recompiles**. |
| Meshscatter count | Raster: indirect, fine | Traced: scenario 4. |
| Mesh topology change | Raster: faces are an index buffer by handle → recompile on a move, stale handle on a rebind (scenario 13) | Traced: a BLAS over box targets is never told about a rebind (box readers are TLAS only, rr:645). |
| Adding a light | Raster: unspecified; Hikari: tables with free lists (plan:1022-1025) | none for Hikari |
| Material type change | New hit group | **recompiles** (plan:1316-1317, api:144) |
| Memory pressure | Evicting arrays recorded by handle (visible flags, index buffers) | **recompiles** after restore (plan:1066-1068) |

**Fixes for the recompile cases:**
- **Material type:** compile all of Hikari's material types as hit groups up front, or one shader with a material-kind tag; a change becomes a store of the tag or SBT offset.
- **Draw order and transparency:** order by depth (z as a model-matrix store) plus order-independent transparency; toggling transparency is two conditional draws switched by stores.
- **Other pipeline switches (shading, linestyle, colour as numbers or colours):** make them runtime values.
- **Traced film:** make film and queue arrays window-sized or resizable.
- **Scene rectangle:** one rectangle array per scene, shared by its plots.
- **Eviction:** never evict resources that have handle dependents, or small ones.
- **Index buffers:** see scenario 13.

### Bugs and holes (most severe first)

1. **Nothing orders a run against reads through a box (race, possible use-after-free).**
   - The run's waits and recorded accesses come only from `pl.summary` (int:700, int:711), and `summary!` does not list array GPURefs (int:519-521).
   - So the frame neither waits for the sim's write nor records its own read, despite plan:1305-1306 and the "their reads recorded" claim at rr:296-297.
   - This breaks `mesh!` of sim arrays and the eager `update!(gpu; positions = …)` path of bench/three_updates.jl.
   - `drophold!` retires with `lasttokens(st.access)` (int:1210-1211), which lacks those frames. After `free!(old)` and a rebind, the old storage can be released while a frame still reads it.
   - Fix: list boxes in `summary!`. At submit, expand each composite's member snapshot (which `lockexpanded` already takes) into the run's waits and `recordaccesses!`.

2. **Eviction never waits for its own copy.** `evictoldest!` retires storage with the copy's token. `acquire!` then only sweeps and retries (int:1005-1009). The token has not passed, so it evicts every idle resource and then throws `OutOfDeviceMemory`. Fix: after evicting enough bytes, `waitfor` the eviction tokens, then sweep.

3. **Combining pending TLAS builds is wrong.** "Only the last is emitted" (rr:491-492). If a `Build` (count changed) is followed by an `Update` in the same submission, only a refit with a new count is emitted, which is invalid (rr:543). Fix: combine to `Build` if any `Build` is pending.

4. **Meshscatter count changes never reach the TLAS.** The range registers on the box (rr:645, rr:850), but `copy!` resizes the box's target, whose `readers` are empty (rr:325).
   - Result: no build is pended, the TLAS count stays stale, and the next build's records kernel writes past the capacity.
   - A plain store does not pend reader updates either (rr:349-356), despite plan:891-893.
   - Fix: the box forwards readers to its current target, re-registering on rebind; a store pends `pendupdate!` on its readers.

5. **`delete!` never removes the TLAS from the range arrays' readers** (rr:573-585, rr:561). Later changes to those arrays pend needless full builds. Fix: readers counted per TLAS.

6. **Two DNNs fail back-to-back.** `evictable` requires every access passed and nothing pending (int:1026-1027), and `acquire!` never waits for in-flight accesses.
   - So `run!(dnn_1); run!(dnn_2)` (ex:347-348) throws while dnn_1 is still on the GPU.
   - Loading dnn_2 right after dnn_1 fails the same way if the constructor's upload is pending or in flight (unspecified).
   - Fix: allow evicting resources with accesses in flight (the copy is ordered after them through the record), then wait for the copy.
   - Separately: on unified-memory devices (M5, Radeon 8060S) Readback memory is the same physical memory, so what eviction frees there is unspecified.

7. **Box targets and TLAS range sources can be evicted without being restored.** They are not plan dependents, so `acquirerestored` never restores them (int:1059-1060). The stale cell keeps the old address, so the next frame or build reads freed memory. Fix: composites register as dependents and restore their members, or exclude composite-held resources from eviction.

8. **`free!(g)` called from its own host function leaks the graph.** It sets `freed` first, then `lockgraph` throws (int:1237-1240). The finalizer sees `freed` already set and skips `release!` (int:1250). Fix: check the owner before the swap, or use a separate "released" flag.

9. **BLAS over kernel-written lengths (Vulkan) is unspecified.** "BLAS builds follow the TLAS's count rules" (plan:888-889) would mean padding over the capacity. Past the length, the sim's arrays hold stale data, which would build garbage triangles. Refit vs build after a sim run is also undecided. Fix: compact into owned geometry with inactive triangles past the length.

10. **Holder types have no finalizers.** `ArrayBox`, `TLAS`, `BLAS` and `RenderObject` have none. The array state's finalizer drops only the creator hold, "the last one" (int:1249-1253), which is false when a box or range also held it. Storage then leaks once all are garbage-collected. Fix: every holder pushes its hold drops through the inbox.

11. **Cells and pending changes are not released in the pseudocode.** `drophold!` retires only `st.storage`. No line anywhere releases a cell from the cell arena. Discarding pending staging, old storage and pages is prose only (rr:694-699).

12. **TLAS `push!` leaks on its error path.** `t.slots[slot] = r`, array holds and readers are taken inside `pend!` before `addhold!(blas)` can throw (rr:557-563). Fix: take holds before `pend!`, as the box rebind does (rr:656).

13. **Index buffers bound by handle.**
    - A box rebind marks nothing: boxes have no dependents (rr:638-646). The recorded `vkCmdBindIndexBuffer` keeps the old buffer, which is released after the rebind applies.
    - api:160's "created with a capacity it never moves" is false: growth past the reserve moves (rr:172-174).
    - Fix: pull indices by address in the vertex stage, or keep all index arrays in one device-wide reserve bound once, with `firstIndex`/`vertexOffset` written by the head.

14. **The first `resize!` always moves** (`growth(dev, ::Region, need)`, rr:169-171), even when shrinking. Fix: a region that still fits becomes `Committed` in place.

15. **`copy!` with a new length copies the old contents** (`MoveStorage … min(sizeof(old), need)`, rr:338-344), then the store overwrites them (rr:358-359). Fix: `copy!` uses a resize that discards contents.

16. **Value updates and same-array rebinds do needless work.**
    - `setattribute!(r, name, value)` allocates a host `Vector` per call (rr:807-808).
    - Rebinding a box to its current target still pends a cell write and two hold changes.

17. **The per-frame record loop.**
    - The model measured 293 µs for 25 000 records (plan:1182-1185). With boxes, a run locks box plus target, so 5 000 plots × 5 attributes is 50 000 records, outside the measured range.
    - api:379's "flat in the number of unchanged plots" test fails by design.
    - Fix: `pend!` and foreign writes push onto a per-plan inbox, so the run touches only that.

18. **Rebinding a box to a view drops the view's static offset, dims and strides.** The box cell holds only the target's cell index (rr:642); offset and strides live in the compiled cell table (int:606-611). Fix: throw for views, or keep the full view description in the box cell.

19. **Transients sized from a host-length array recompile past twice its length** (`SizedBy`, rr:420-421). Fix: size resizable arrays from their reserve.

20. **`writeentry!` waits on every run of a plan with any GPURef** (int:798-806). Since `ArrayBox <: GPURef` (rr:635-638), `gpurefs` is ambiguous, and boxes have no `value` field. Fix: a GPURef value store marks its plans.

21. **Unmapping pages beyond an array's size is contradictory.** Pressure unmaps them (plan:1027-1029, int:1175), yet "shrinking never unmaps … so a view never reads unmapped memory" (int:63-65, rr:196-197).

22. **Window-sized images use the monitor-size capacity regardless of the window** (plan:836-838). Fix: since window-sized segments are re-recorded per swapchain generation anyway (plan:951-953), create the targets per generation at the actual size.

23. **Unspecified.**
    - When Hikari's integrator graph runs relative to the frame graph: the render loop runs only the frame graph (rr:824-830), while plan:1221-1222 says parts that always run together are one graph.
    - Who clears the shadow/AO `when!` flags (plan:1311-1313).
    - A BLAS topology change: "TLASes pend a build" (rr:622-625) vs "a TLAS refit" (plan:881-884).
    - Metal visibility. Fix: the head writes count × visible into the indirect command, which needs no conditional rendering on any device type.

## 3. Rule violations in the pseudocode

- **`isa` branches (A2):** int:656, int:1071, rr:306, rr:328. rr:239 and rr:274 are annotated "a method per … in real code".
- **Catch-all with rethrow (A2):** `when!` at int:276-284 and `holdparts!` at int:746-761. Use `finally` with a success flag, as `recompile!` does (int:650-668).
- **Detection at `run!` (A4):**
  - `current!` compares `(count, storage)` against what was recorded (rr:530-534). Fix: TLAS changes push a stale mark onto its `AccelCommand`s.
  - `bindunmapped!` compares mapped bytes against the peak at run (int:1184-1192), against plan:1047 "Nothing compares sizes at run!".
  - Borderline: the snapshot `===` check on every submission (rr:303) and the compare in `register!` (rr:392-398).
- **Policy inside device verbs (A1):** `reservesize`, `sparsethreshold` (rr:169-178, rr:705-706, api:244-245) and `submissionbudget` (plan:496-499).
- **Globals:** only `REGISTRY` (int:1364), which is allowed. ex:403 has a non-const global, `SCATTER`, in example code.
- **Clean:** no `_`-prefixed function names, no `hasproperty`/`hasmethod`/`applicable`, no ambient state.
- **Type and signature mismatches:**
  - `readers::WeakSet{TLAS}` (rr:193), yet BLASes and the screen are readers too (api:135, plan:1307-1308).
  - `push!(t, blas, source::MantleArray)` (rr:554) is called with a box (rr:850).
  - `addhold!(a)` is called on an array (rr:561) instead of its state.
  - `retire!(old, c.lasttoken)` (rr:540) does not match `retire!(pool, x, tokens)`.
